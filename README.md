# RMGAF

检查并修复 RPG Maker **MV / MZ** 游戏资源路径的大小写差异。以 `data/*.json` 为主直接扫描，不需要启动游戏，也不执行游戏中的 JavaScript。

```console
rmgaf /path/to/game --check
rmgaf /path/to/game
```

传入 **`index.html` 所在目录**：MV 部署包通常是 `www`，MZ 通常与 `nw.exe` 同级

## 安装与运行

需要 Python 3.11+。在本项目目录：

```sh
uv sync
uv run rmgaf "/path/to/index.html 所在目录" --check
uv run rmgaf "/path/to/index.html 所在目录"
```

安装为全局命令：

```sh
uv tool install .
rmgaf "/path/to/game" --check
```

也可使用 `pip install .`，或安装后通过 `python -m rmgaf` 调用。项目尚未发布到 PyPI。

## 使用

| 参数 | 行为 |
| --- | --- |
| `rmgaf <dir>` | 检查并执行无歧义的大小写重命名 |
| `--check` | 只读扫描，不修改游戏文件 |
| `-v` / `--verbose` | 显示全部差异、问题及引用来源 |
| `--no-color` | 关闭颜色和动画；也支持 `NO_COLOR` 环境变量 |
| `--version` | 显示版本 |
| `--help` | 查看用法 |

交互终端显示扫描动画、当前文件、资源统计、重命名差异与耗时；重定向到文件或管道时不输出动画与 ANSI 颜色。默认限制差异展示数量，大量问题可用 `--verbose` 完整输出。

```sh
rmgaf ./www --check --verbose > report.txt
```

退出码：`0` 表示扫描范围内没有遗留问题；`1` 表示存在待修复大小写、缺失资源、冲突或无法完整读取的数据；`2` 表示命令参数、目录或 I/O 错误；中断为 `130`。`--check` 发现大小写问题时返回 `1`，便于脚本/CI 使用。

## 检查范围

**JSON 优先：** 枚举 `data` 下的 JSON，按 MV/MZ 标准字段和事件指令解析资源名；不会把剧情文本中的任意字符串猜成文件名。

- 角色行走图、头像、战斗图；敌人图及横版/正面战斗目录。
- 系统标题、战斗背景、载具、BGM/ME/SE；MZ 字体。
- 地图、事件页、公共事件、战斗事件、移动路线中的图片、音频、视频。
- 图块、远景、MV 动画图片/音效、MZ `.efkefc` 动画文件及音效。
- 标准数据库文件名、`MapInfos.json` 中引用的地图文件。
- MV `.rpgmvp` / `.rpgmvo` / `.rpgmvm`；MZ `.png_` / `.ogg_` / `.m4a_`。依据 `System.json` 的加密标志转换路径，不修改或解密资源内容。支持 MV 静态 `Decrypter._ignoreList`。
- 音频 `.ogg` / `.m4a`、视频 `.webm` / `.mp4` 作为备选格式；已有的各格式都会对齐，不会要求未部署的备选格式必须存在。

**补充静态发现：** 检查 `index.html`、关联 CSS、入口脚本及启用插件。解析常见 `ImageManager`、`AudioManager`、字体/视频加载调用的字面量，支持静态字符串拼接与转义；读取 `js/plugins.js` 及插件 `@type file` / `file[]` / `struct` 参数。JavaScript 使用语法树解析，不运行脚本。补充线索只在文件存在时参与对齐，未找到的可选脚本引用不会被当作确定缺失。

即使在大小写不敏感的 macOS / Windows 文件系统上，也会通过实际目录项比较大小写，而不是依赖 `exists()` 的结果。

## 修复与数据安全

修复以**引用请求的拼写**为准，只重命名资源文件和必要的目录，不改 JSON、脚本内容、剧情、存档，也不统一强制改为小写。

- 同一资源被要求使用两种不同拼写，或存在仅大小写不同的多个文件/目录：报告冲突，**整次修复不写入**。
- JSON 无法读取、路径越界或引用指向符号链接：报告阻塞，不静默漏过后继续修复。
- 真正缺失的资源单独报告，不下载、不伪造；不阻止其他无歧义的大小写修复，修复后仍返回 `1`。
- 目录由深到浅改名；通过中间名支持大小写不敏感文件系统上的 case-only rename。
- 目标已存在时不覆盖；普通 I/O 失败或 Ctrl+C 时逆序回滚已完成的改名，回滚失败会明确报告。

**修复前关闭游戏并备份目录。** 不支持与游戏、同步程序或另一修复进程并发改动目录；断电、强制终止或硬盘故障不保证自动恢复。

## 静态分析边界

“没有发现问题”只针对已识别的静态引用，不等于所有游戏分支均已运行验证：

- 无法穷尽由变量、运行时计算、网络请求或自定义加载器生成的文件名。
- 不猜测插件自定义 JSON 字段、备注标签或未声明类型的裸资源名；不扫描存档及停用插件，不解析第三方 `js/libs` 的代码。
- 不解析 `.efkefc` 内部二进制纹理依赖；不解释 HTML `<base>` 或任意复杂 CSS 语法。
- MV/MZ 标准资源加密受支持，但**插件自定义的 JSON 加密/压缩格式不属于标准格式**。请在副本中用该游戏自己的格式还原 JSON 后检查；工具遇到不可读 JSON 会阻止修复。

## 开发与验证

```sh
uv sync
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
uv build
```

行为测试覆盖 MV/MZ 加密扩展名、事件索引、目录大小写、Unicode/静态 JS 解析、冲突拒绝、缺失资源、符号链接、I/O 回滚、只读检查与修复幂等性。仅大小写不同的双文件冲突测试需大小写敏感文件系统；其他平台会跳过该条。

已完成实测：大小写敏感 HFS+ 临时卷上 **26 项测试通过**；构建后的 wheel 在隔离环境中成功运行 MZ 样本检查。参考 MV 游戏副本还原 11 个自定义加密 JSON 后，扫描 9,734 个文件、530 个来源，发现 6 处真实大小写差异及 170 个未匹配引用；6 处差异与另行注入的 1 处错误均成功修复，二次扫描无待改名项，注入资源的内容哈希不变。未启动游戏逐分支验证；170 个未匹配引用仍需结合插件运行行为判断。

`tree-sitter` 暂限定在 `0.25.x`：`0.26.0` 在参考游戏解析时发生原生崩溃，与[上游 Node 遍历回归报告](https://github.com/tree-sitter/py-tree-sitter/issues/472)一致；同一输入已用 `0.25.2` 验证。
